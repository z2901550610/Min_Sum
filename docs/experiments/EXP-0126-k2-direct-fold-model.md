# EXP-0126：二层Karatsuba直接折叠的算法与调度预算

日期：2026-09-09。状态：软件模型PASS，候选RTL/Yosys/Vivado均NOT_RUN。
这是对现有单Comba、SDP操作数绑定的候选评估，未替换生产一层核，也未修改旧EXP-0119候选。

## 候选结构

定义`Q=ceil(W/4)`。九个quarter乘积依次计算，每个子积的重组偏移沿用二层恒等式：
`[0,1,2,3] / [1,2,3,4] / [1,3] / [2,3,4,5] / [3,4,5,6] / [3,5] / [2,3] / [3,4] / [3]`，单位Q words。
每个叶子word立即截断到低2r位并循环折叠到独立W-word结果RAM，不保存完整product RAM。

三个内层乘法各进行两次Q-word XOR扫描，外层进行两次2Q-word扫描；
共10Q个原地更新，每个READ_LOW/READ_HIGH/WRITE_LOW三拍，即30Q拍。
顶层与内层输入按逆序恢复。逻辑quarter补齐到4Q；拟议物理映射仍使用原W-word RAM，
虚拟位置固定读零、按公开几何禁止虚拟写入。该映射尚未建立RTL时序或形式证明。

## 周期预算及限制

在每条对角线一拍prefetch、每个子积word一拍advance、每份贡献两拍RMW的假设下：
`T_K2 = 9Q² + 166Q + 5W - 7 + 2S2`。
S2为非对齐r下25个偏移序列落入`[W-1,2W-2]`的word数；word对齐时为零。
166Q包含18Q对角线项、18Q advance、100Q结果RMW和30Q输入扫描。
实际RTL额外状态、地址时序及padding处理可能改变预算，不能把预算称为RTL实测。

| r | 当前K1周期公式 | K2候选预算 | 预算降幅 |
| --- | ---: | ---: | ---: |
| 12589 | 35149 | 34368 | 2.22% |
| 15581 | 51733 | 47902 | 7.41% |

上表保留2026-09-09未重叠K1基线。当前模型的K1列已计入Comba/折叠重叠；
r15581当前K1为47,439拍，低于本K2候选的47,902拍预算。参见[当前架构](../design/trike_karatsuba_fold.md)。

复现（输出当前K1基线）：`./eda python3 scripts/model_trike_k2_fold.py --r-bits 12589 15581 106781`。
13种小边界及3种大几何，每种zero/all-one/seeded-random，共48例；
九叶重组/截断/直接折叠结果与独立cyclic_multiply参考相同，操作数恢复通过。
日志：`build/encaps-dense/k2-model.log`。

## 决策

当前Encaps首先保留一层稠密核。K2在TRIKE-2的理论预算优势有限，增加了扫描、重组和虚拟地址控制；
没有资源/时序证据前不迁入主线。大r保留为后续候选，下一步必须建立真实SDP RAM绑定的RTL并验证预算，
再进行同条件Vivado比较；不得拿旧EXP-0119完整product RAM的资源结果代替本候选。
