# 项目记录规则

以最少维护量保存当前设计和可复用结论，不记录探索流水账。执行与验证规则只维护在
[工作流](workflow.md)，本文只定义什么值得写入仓库。

| 内容 | 唯一维护位置 | 何时更新 |
| --- | --- | --- |
| 普通修改、调试、测试输出 | Git、现有自动日志 | 不另写总结文件 |
| 当前接口、RAM生命周期、固定周期 | 所属[设计文档](README.md) | 采用的设计事实改变时 |
| 当前验证范围与限制 | [实现状态](design/implementation_status.md) | 有新结果或旧结果失效时，仅更新受影响项 |
| 有证据放弃的方向 | [错题与历史索引](experiments/index.md) | 能避免重复探索时，一条机制只记一次 |
| 有价值但未完成的候选 | [路线图](design/trike_kem_optimization_roadmap.md) | 确需跨任务保留时，只写候选和进入条件 |
| 正式物理结果 | RUN manifest、原始报告、[基线注册表](design/vivado_baseline_registry.md) | 按现有物理证据规则 |

## 记录门槛

阅读、推导、参数试点和中间实现默认留在对话与工具输出，不创建计划、日报、阶段总结或预占EXP。
普通编译错误、修复后通过的bug不进入错题本。只有证据表明某方向在当前约束下不值得继续，且具有
复用价值时，记录“方向/条件、失败原因、关键证据及复现位置、重新考虑的条件”。默认一行或一段；
只有无法简述的失败机制或正式比较才用[单项模板](experiments/template.md)。不为填表补跑无关测试。

未测、暂停、CANCELLED与NOT_RUN不是失败；局部Yosys估计不是Vivado结论。成功方案只更新所属
设计说明及必要验证边界，不同步改写每个索引、路线图和历史文件。用户明确要求的论文、报告等交付物除外。
历史EXP和冻结探索史保留原路径、ID、配置与证据，不继续追加过程，不默认全文读取。

## 物理证据与生成物

正式Vivado比较沿用一个EXP关联多个RUN，索引一行即可，不要求单项文档。
每次执行的RUN manifest和原始报告规则见[manifest规范](../reports/vivado/manifests/README.md)。
只有器件、工具、XDC、参数、defines、存储几何与报告阶段可比的完整routed结果才能更新物理基线。
旧记录的pending表示历史决策状态；新验证结果用PASS/FAIL/NOT_RUN/NOT_APPLICABLE，并单列取消范围。

可重建fixtures、日志、波形、综合输出留在已有build/report目录，不把完整输出搬进文档。
工具升级与验证入口见[工作流](workflow.md)及[环境基线](environment.md)；本文不另设执行流程。
